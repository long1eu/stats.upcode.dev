Field service that works with no signal.

C-1The problem

Contractors work in basements, new builds and rural sites. A crew lead who can't open a job, clock in or take a payment because the signal dropped stops using the app, and goes back to paper. The app had to treat the network as optional: every screen readable offline, every change saved locally and delivered later, in the right order.

C-2How it works

Local first, always

Every read shows what is stored on the device first, then refreshes from the server in the background and updates only if something changed. Screens open instantly, online or not, and nothing errors when the signal is gone.

A write queue that survives anything

Changes are operations in a queue persisted to SQLite, so they survive the app being killed. Each one knows what it depends on: an invoice line waits for its invoice, a payment for both. 138 operation types, up to three running at once so one large photo upload never holds up a clock-in.

Connectivity you can trust

Online and offline are decided by whether the app's own server answers, not by pinging the internet. Three failed requests in a row switch to offline; a health check every five seconds switches back, and the queue drains the moment it does.

Storage that respects old data

Records are stored as Protobuf generated from the app's models, with field numbers pinned in a ledger so a schema change can never misread what is already on a user's phone. 141 message types, still readable after every schema change.

C-3Shipping it

Every change is reviewed, and every merge to the main branch can become a build for testers. Releases move from dev to release candidate to the stores through scripted CI on our own Mac build machines, and Dart-only fixes go out as code-push patches, reaching users in hours instead of waiting on store review.

  • 2,300+ commits since May 2022, 155 unit and widget test files and 10 end-to-end suites covering offline sync, invoices, jobs and timesheets.
  • Card payments on invoices, including Tap to Pay, so the phone itself takes a contactless card on site.
  • macOS and Windows builds of the same codebase, used by the team and by AI agents to test without a phone.
  • A one-tap "send my data to support" that uploads a copy of the local database, so offline bugs can be reproduced exactly.

Release volume has grown with the product: 75 builds in 2023, 202 so far in 2026.
